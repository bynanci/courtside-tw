# Reviewed basketball intake

Canonical recap inputs can be created through the authenticated editorial API. No database editing or provider activation is required. `PUBLISHER` uses `/api/v1/publisher/basketball`; `ADMIN` uses `/api/v1/admin/basketball`. The existing OIDC role boundary keeps these namespaces separate.

1. `POST /snapshots` submits a rights-approved source reference. Supply the immutable source identity, a new snapshot UUID, a new evidence UUID, minimal source content, a rights reference, confidence, and explicit publication/effective/freshness dates. Unknown publication or effective dates are JSON `null`. The server records retrieval time, computes SHA-256, and assigns `REPORTED`. It never fetches the URL.
2. `GET /evidence/{evidenceId}` returns the retained source, snapshot, evidence reference and private review history for inspection.
3. `POST /evidence/{evidenceId}:confirm` requires a separate `confirmedEvidenceId` and a human review rationale. The server derives the reviewer from authenticated identity and records its own decision time. It retains the original `REPORTED` reference and snapshot. Future, stale, expired, undated or analysis evidence cannot become confirmed factual input through this workflow.
4. `POST /facts` accepts `{ "kind": "SEASON", "payload": { ... }, "rationale": "..." }`. The payload uses the existing Java domain record fields; the wrapper supplies the discriminator. Submit prerequisite identities before their relationships: for a season recap, create the league and team, then the season, then each team-season participation. Use the newly reviewed evidence IDs in every evidence list, including aliases and roster entries. The same endpoint supports existing player, career, competition, tournament, game, campaign, roster and alias records without changing their temporal or append-only rules.

Each request creates at most one canonical fact. A snapshot permits 1–16,000 characters of approved reference material; the entire JSON command is limited to 65,536 characters. A canonical payload is limited to 48,000 characters, 32 entries per nested collection, 32 distinct evidence references and eight nested levels. Unknown properties, duplicate JSON keys, scalar coercion and fractional integer revisions are rejected.

UUID identities are immutable retry keys. Identical source material and decisions retain their original metadata; changed bytes or a changed decision return conflict. Human review events are private audit records. A review is retained before the subsequent catalog append and does not assert that the catalog transaction has committed. Failed steps can be retried with the same identities; an unreviewed reference never authorizes a canonical fact. Canonical relationships validate under the catalog lock, and evidence freshness and contradiction state are rechecked after acquiring that lock.

The season recap generator consumes stored season/team-season facts, derives its values from their periods, and independently checks evidence and poster rights at projection time. Creating canonical input does not bypass publication or rights checks. All intake responses are private and `no-store`; raw source content and reviewer metadata are not recap payload fields.
