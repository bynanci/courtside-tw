# TAIWAN HOOPS ARCHIVE

> **台籃文化數位雜誌 × 球迷 Season Passport × 可驗證出版檔案**

以台灣籃球為核心，持續記錄 **中華隊、旅外球員、TPBL、P. LEAGUE+（PLG）與 SBL** 的比賽、人物、戰術、產業、主場文化與歷史脈絡。

Web3 在本專案中不是投機商品或閱讀門檻，而是可選用的「收藏、身份、溯源與支持」基礎設施。

## 1. 專案一句話

建立一個能把台灣籃球的「當下賽事」與「長期文化記憶」放在同一條時間線上的數位雜誌，並讓讀者能收藏期刊、累積球迷身份、支持創作者，以及驗證文章與素材的出版版本。

---

## 2. 產品定位

TAIWAN HOOPS ARCHIVE 不是：

- 即時比分 App 的複製品。
- 只追逐流量的賽後新聞站。
- 球員卡炒作平台。
- NFT 交易市場。
- 付費牆包住所有內容的封閉媒體。
- 由持幣數量決定新聞真假的 DAO。

它真正要做的是：

```text
賽事與人物採訪
        ↓
編輯整理與資料驗證
        ↓
期刊、長文、戰術圖解與動態封面
        ↓
建立跨聯盟、跨賽季、跨國家的台籃時間線
        ↓
保存出版版本、創作者署名與素材授權
        ↓
讓球迷收藏自己參與台籃文化的紀錄
```

核心價值：

1. **內容深度**：不只報比分，也解釋角色、戰術、脈絡與後續影響。
2. **台灣視角**：中華隊、旅外球員與本土聯盟不是分散頻道，而是同一個人才與文化系統。
3. **可追溯**：文章、資料、圖片與修訂都有來源、時間與版本。
4. **可累積**：讀者的閱讀、觀賽、活動與文化貢獻能形成個人球迷年鑑。
5. **創作者可持續**：作者、攝影、插畫、資料編輯與 Motion Designer 的貢獻可被清楚標示與支持。

## 3. 為什麼需要這個產品

台籃資訊並不少，真正缺的是能長期保存與交叉理解的結構。

目前常見問題：

- 中華隊、旅外球員與國內聯盟被拆成不同新聞流，難以追蹤人才發展全貌。
- 比賽資訊快速消失在社群貼文、短影音與即時新聞中。
- 同一位球員跨聯盟、跨國家、跨賽季後，歷史資料難以串接。
- 球隊更名、聯盟改組、賽制調整後，舊內容容易失去脈絡。
- 數據、傳聞、記者報導與官方公告常混在一起，讀者難以判斷可信度。
- 攝影、影片、Logo、球衣與球員肖像的權利範圍容易被忽略。
- 球迷參與只留下票根與相簿，缺乏可持續累積的文化身份。

本專案將這些問題整合成一套「內容、資料、證據、權利與球迷身份」系統。

### 4.1 中華隊｜Chinese Taipei

FIBA 登錄名稱為 **Chinese Taipei（TPE）**。內容涵蓋：

- 男子與女子成人代表隊。
- 亞洲盃、世界盃與奧運資格賽等國際賽事。

- 培訓名單、最終名單、傷病與徵召變動。
- 歸化、旅外、本土聯盟球員的角色整合。
- 對手偵察、比賽計畫、輪替與攻防影片分析。
- 國際賽窗口期與國內賽季的衝突及負荷管理。
- 歷屆賽事、經典比賽、球衣、場館與球迷文化。

建議固定欄目：

| 欄目 | 內容 |
| --- | --- |

### 4.2 旅外球員｜Taiwan Abroad

旅外不是單純整理得分，而是追蹤球員在不同籃球環境中的角色演化。

涵蓋範圍：

- 日本 B.LEAGUE、B3、W LEAGUE。
- 中國 CBA、WCBA 與其他亞洲聯賽。
- 美國 NCAA、NJCAA、NAIA、G League 與發展體系。
- 歐洲、澳洲及其他職業或半職業聯賽。
- 青年留學、訓練營、試訓與短期合約。

每位旅外球員至少追蹤：

```ts
interface OverseasStint {
  playerId: string
  country: string
  league: string
  team: string
  season: string
  contractStatus: 'CONFIRMED' | 'REPORTED' | 'TRIAL' | 'ENDED' | 'UNKNOWN'
  role: string | null
  gamesPlayed: number | null
  minutesPerGame: number | null
  usageNotes: string | null
  lastVerifiedAt: string
  sources: EvidenceRef[]
}
```

內容不只回答「今天拿幾分」，還要回答：

- 他在球隊扮演什麼角色？
- 上場時間與球權為什麼改變？
- 教練如何使用他？
- 所屬聯賽的規則、外援制度與競爭強度是什麼？
- 旅外經驗如何影響中華隊或返台後的打法？
- 合約、傷病、登錄與轉隊資訊是否已有官方確認？

> 旅外名單變動頻繁，不在前端程式或 README 中硬編碼。名單必須由資料層管理，並保存 `asOf` 與來源。

## 5. 編輯主張

### 5.1 Taiwan-first，不是 League-first

不以聯盟站隊，而以台灣籃球整體發展為判準。

同一位球員可能經歷：

```text
HBL → UBA → SBL → TPBL／PLG → 旅外 → 中華隊 → 返台
```

產品資料與編輯敘事都必須能保存這條完整路徑。

### 5.2 Evidence before opinion

每一則內容要區分：

| 標記 | 定義 |
| --- | --- |
| `CONFIRMED` | 官方公告、正式賽事資料或當事人直接確認 |
| `REPORTED` | 可信媒體報導，但尚未獲官方最終確認 |
| `ANALYSIS` | 依比賽、影片或資料做出的編輯分析 |
| `RUMOR` | 未具充分證據的市場或社群傳聞 |
| `UNKNOWN` | 資料不足，暫不做確定陳述 |

`RUMOR` 不得被寫成 `CONFIRMED`，模型生成內容不得自動升級證據等級。

### 5.3 League-neutral

- 不因合作、贊助或持有收藏品改變編輯結論。
- 球迷投票只能影響選題優先級，不能決定事實真偽。
- 球團與贊助商不得控制更正、評論或負面議題的結論。
- 商業合作內容必須清楚標示。

### 5.4 Correction is a feature

錯誤修正不能只覆蓋舊文章。

每次更正都應保存：

- 原始版本。
- 修正版本。
- 修正原因。
- 修正時間。
- 影響範圍。
- 編輯核准者。
- 前後版本 hash。

### 6.1 日常內容

- 即時但經確認的新聞摘要。
- Game Day 賽前指南。
- 賽後重點與數據拆解。
- 旅外球員每日／每週追蹤。
- 傷病、登錄、轉隊與名單異動。

### 6.2 每週內容

- 台籃 Power Ranking。
- 中華隊與旅外狀態週報。
- TPBL／PLG／SBL 戰術趨勢。
- 一週五個值得重看的回合。
- 主場文化與球迷內容精選。

### 6.3 月刊／主題期刊

每一期是一個具有明確編輯命題的完整作品，而不是文章集合頁。

範例：

- 《窗口期：中華隊如何重新建立防守身份》
- 《島外生存：旅日台將的一季角色變化》
- 《雙職籃之後：台灣主場文化長成了什麼》
- 《SBL 人才供應鏈：被忽略的下一批即戰力》
- 《台灣後衛製造論》
- 《一座球館如何長出一群球迷》

每期可包含：

- 封面故事。
- 3–6 篇深度文章。
- 球員或教練訪談。
- 戰術圖解。
- 數據專題。
- 攝影或插畫企劃。
- p5.js 動態封面。
- 來源與權利清單。
- 可選的 Reader Stamp 或 First Press Edition。

### 6.4 賽季年鑑

賽季結束後產出：

- 中華隊年度回顧。
- 旅外球員年度報告。
- TPBL／PLG／SBL 聯盟年鑑。
- 球員與球隊時間線。
- 個人化球迷 Season Recap。

## 7. 核心使用者體驗

### 7.1 公開閱讀

```text
首頁
→ 選擇中華隊／旅外／TPBL／PLG／SBL
→ 閱讀期刊或文章
→ 查看來源、更新時間與作者
→ 收藏、追蹤或分享
```

原則：

- 閱讀不要求錢包。
- 文章可被搜尋引擎索引。
- 分享連結不要求登入。
- Web3 服務中斷不能影響閱讀。
- 核心內容支援無 JavaScript 的基本閱讀降級。

### 7.2 球員時間線

```text
球員頁
├─ 基本資料
├─ 所屬球隊與旅外經歷
├─ 中華隊經歷
├─ 賽季與比賽數據
├─ 文章與訪談
├─ 傷病／登錄／轉隊紀錄
└─ Evidence Timeline
```

### 7.3 球迷護照

```text
完成閱讀或活動條件
→ 點擊「收進我的台籃護照」
→ Email／Google／Apple 登入
→ 建立一般帳號
→ 使用者選擇是否建立內嵌錢包
→ Sponsored transaction
→ Credential 領取成功
```

使用者感受應是「收藏台籃記憶」，不是「操作金融商品」。

## 8. Web3 整合策略

### 8.1 原則

```text
Magazine Core ≠ Blockchain
Magazine Core 可以獨立運作
Web3 Adapter 可以被 feature flag 關閉
```

Web3 只處理四件事：

1. **收藏**：保存某一期、某個活動或某段賽季記憶。
2. **身份**：形成可攜帶的球迷 Season Passport。
3. **溯源**：錨定正式出版版本、署名與修訂關係。
4. **支持**：讓核心讀者支持媒體與創作者。

### 8.2 Issue Edition

每一期可有三種版本：

#### Public Edition

- 免費閱讀。
- 不需登入或錢包。
- 所有文章可公開分享。

#### Reader Stamp

- 完讀、活動參與或完成知識測驗後免費領取。
- 預設不可轉讓。
- 不宣稱投資或升值價值。
- 表示「我曾參與這一期」。

#### First Press / Patron Edition

- 限量或限定期間。
- p5.js 動態封面。
- 獨立 Edition ID。
- 清楚列出作者、攝影、插畫與 Motion 署名。
- 可附實體刊物優先權、活動資格或作者 AMA。
- 購買的是支持與紀念，不是文章著作權。

### 8.3 Season Passport

可累積的 Credential：

| 類型 | 範例 | 預設可轉讓 |
| --- | --- | --- |
| `ISSUE_READER` | 收藏某一期 Reader Stamp | 否 |
| `NATIONAL_TEAM_WINDOW` | 完成中華隊窗口期專題 | 否 |
| `GAME_ATTENDEE` | 經驗證參加特定賽事 | 否 |
| `EVENT_ATTENDEE` | 參與講座或球迷聚會 | 否 |
| `QUIZ_COMPLETED` | 完成戰術或歷史測驗 | 否 |
| `ARCHIVE_CONTRIBUTOR` | 提供經採用的票根、照片或口述史 | 否 |
| `CREATOR` | 作者、攝影、插畫或資料編輯 | 否 |
| `PATRON` | 支持特定期刊或年度方案 | 依方案設定 |

### 8.4 p5.js 動態封面

Motion Cover 可以由合法取得的比賽資料、編輯主題與 Edition Seed 驅動：

```ts
interface MotionCoverInput {
  issueId: string
  scope: 'NATIONAL_TEAM' | 'OVERSEAS' | 'TPBL' | 'PLG' | 'SBL'
  season: string
  editorialTheme: string
  gameSignals?: {
    scoreMargin: number
    leadChanges: number
    pace: number | null
    quarterSwing: number[]
    shotZoneDistribution: number[] | null
  }
  editionSeed: string
  publicationHash: string
}
```

資料與視覺的對應範例：

- 領先變化控制線條方向。
- 比數差距控制畫面張力。
- Pace 控制動態速度。
- 出手區域形成幾何熱區。
- 賽季或聯盟主題控制排版節奏。
- Edition Seed 產生有限但可重現的變體。

### 8.5 Publication Proof

鏈上只保存需要公開驗證的最小資料：

```ts
interface PublicationProof {
  publicationId: string
  issueId: string
  articleId: string | null
  version: number
  contentHash: string
  metadataHash: string
  rightsManifestHash: string
  contributorIds: string[]
  publishedAt: string
  previousVersionHash?: string
  correctionReason?: string
}
```

不把完整文章、合約與個人資料塞上鏈。

### 8.6 不做的 Web3 功能

MVP 明確排除：

- ERC-20 或任何平台代幣。
- 質押、利息、保本或報酬承諾。
- 二級交易市場。
- 平台代管使用者資產。
- 以持幣量控制編輯權。
- 強迫讀者購買加密貨幣或支付 Gas。
- 把完整閱讀紀錄與行蹤公開上鏈。
- 未取得授權的球員卡、比賽影片或球隊 Logo 收藏品。

## 11. 資料與證據政策

### 11.1 來源優先序

1. FIBA、籃協、聯盟、賽事與球團官方資料。
2. 當事人正式聲明、記者會與直接訪談。
3. 具編輯責任的可信體育媒體。
4. 經交叉驗證的記者或專業工作者資訊。
5. 社群訊號。
6. 模型推導或編輯推論。

低層級來源不得覆蓋高層級已確認資料，除非高層級來源已過期或存在明確矛盾。

### 11.2 Freshness

每筆可變資料必須包含：

```ts
interface FreshnessMeta {
  sourceAsOf: string
  retrievedAt: string
  expiresAt: string | null
  freshness: 'LIVE' | 'RECENT' | 'DELAYED' | 'STALE' | 'EXPIRED' | 'UNKNOWN'
}
```

適用資料：

- 球員目前球隊。
- 旅外合約狀態。
- 傷病與登錄。
- 賽程、比分與戰績。
- 中華隊培訓與最終名單。
- 球隊名稱與聯盟成員。

### 11.3 矛盾處理

```text
來源衝突
→ 標示 DISPUTED
→ 保留各來源與時間
→ 不輸出單一確定結論
→ 指派人工編輯覆核
→ 更新後保留 Decision Trail
```

### 11.4 AI 使用規則

AI 可以：

- 協助摘要與翻譯。
- 辨識人物、賽事與主題關聯。
- 產生訪綱、草稿與資料檢查建議。
- 協助比對版本與來源矛盾。
- 輔助戰術影片標記與資料視覺化。

AI 不可以：

- 自行把傳聞升級成事實。
- 捏造引言、數據或比賽內容。
- 在未審核下發布人物指控。
- 推定球員傷病、心理或合約狀況。
- 取代圖片、影片與肖像的授權確認。

## 12. 權利與素材模型

每個圖片、影片、Logo、球衣、音訊與 Motion 素材都必須有 Rights Manifest：

```ts
interface RightsManifest {
  id: string
  assetId: string
  rightsholder: string
  licenseType: 'OWNED' | 'LICENSED' | 'PRESS_USE' | 'FAIR_USE_REVIEW' | 'UNKNOWN'
  permittedUses: Array<
    | 'EDITORIAL_WEB'
    | 'SOCIAL_PROMOTION'
    | 'PRINT'
    | 'PAID_MEMBERSHIP'
    | 'DIGITAL_COLLECTIBLE'
  >
  territory: string[]
  startsAt: string | null
  expiresAt: string | null
  transferable: boolean
  collectiblePermission: 'GRANTED' | 'DENIED' | 'NOT_REVIEWED'
  contractRef: string | null
}
```

硬性規則：

```text
collectiblePermission !== GRANTED
→ 禁止鑄造或發行數位收藏版本
```

一般網站刊登權不等於數位收藏品發行權。

## 16. 法遵與智慧財產邊界

### 16.1 IP 並不會因為上鏈而自動取得

- 球員照片需要攝影著作權與必要的肖像／商業使用授權評估。
- 比賽精華、轉播畫面與音訊不得因為被轉成 NFT 就視為合法。
- 聯盟、球團、賽事名稱、Logo、球衣與吉祥物須分別檢查授權。
- 一般新聞或網站使用授權不一定涵蓋付費會員、印刷或數位收藏。
- 收藏品持有人取得的權利必須寫入明確條款。
- 不得暗示持有人取得文章、圖片、球員肖像或品牌的著作權與商業使用權。

### 16.2 虛擬資產服務風險

若產品延伸至以下功能，必須先做台灣法規與營運模式的正式法律審查：

- 交易平台。
- 代管錢包或私鑰。
- 資產交換與移轉服務。
- 承銷、借貸或收益設計。
- 穩定幣或平台代幣。
- 法幣與虛擬資產兌換。

MVP 刻意避開上述服務，以降低不必要的金融監理、資安與消費者保護風險。

### 16.3 安全起始邊界

```text
自行創作或已取得完整授權的內容
＋ 公開免費閱讀
＋ 可選、非投資性的紀念 Credential
＋ 不提供交易市場
＋ 不代管可交易資產
＋ 不承諾價格、收益或保本
```

> 本章為產品風險設計，不構成法律意見。正式上線前應由熟悉台灣著作權、肖像權、個資與虛擬資產法制的律師依實際流程審查。

## 22. Definition of Done

一個功能不因「畫面看得到」就算完成。

### 一般功能

- Domain model 與 API 契約明確。
- Happy path、錯誤、空狀態與 stale 狀態都有設計。
- Mobile-first 與 safe-area 通過。
- 核心資料有 evidence 與 `asOf`。
- Log、metric、trace 與錯誤追蹤可用。
- Unit、integration 或 E2E 測試覆蓋主要風險。

### Web3 功能

- 不阻斷非 Web3 使用者。
- Claim 具 idempotency。
- Feature flag 可立即停用。
- 鏈上與鏈下狀態可 reconciliation。

## 23. 主要風險

| 風險 | 影響 | 控制方式 |
| --- | --- | --- |
| 聯盟與球隊快速變動 | 名稱與頁面失真 | canonical ID、alias、`asOf`、動態設定 |
| 旅外資訊分散 | 錯報合約與角色 | 來源分級、人工覆核、狀態標籤 |
| 圖片／影片未授權 | 下架、賠償、品牌傷害 | Rights Manifest、Publish Gate |
| Web3 認知偏差 | 被視為炒作平台 | 免費閱讀、無平台幣、不可轉讓優先 |
| 錢包 UX 複雜 | 使用者流失 | Email-first、off-chain-first、可跳過 |
| 鏈與供應商綁定 | 成本與遷移困難 | Adapter／Port、鏈抽象化 |
| 資料來源失效 | 錯誤或過期資訊 | Adapter health、freshness、降級 |
| 編輯與商業衝突 | 公信力下降 | 合作揭露、編輯防火牆、Conflict Check |
| 公開行蹤風險 | 球迷隱私受損 | 最小上鏈、預設私密、模糊化活動資料 |
| 冒名與假收藏品 | 詐騙與品牌損害 | 官方驗證頁、合約地址 Registry、警示機制 |

## 24. 專案決策原則

遇到產品取捨時，依序判斷：

1. 是否提升台籃內容品質與歷史保存？
2. 是否讓中華隊、旅外與本土聯盟的關係更清楚？
3. 是否有可信資料、授權與可驗證版本？
4. 是否在手機上容易閱讀與操作？
5. 是否不使用 Web3 也能成立？
6. Web3 是否真的提供收藏、身份、溯源或支持價值？
7. 最壞情況發生時，是否能停用並回到內容核心？

若第 5 題答案是否定的，代表架構方向已經偏離。
